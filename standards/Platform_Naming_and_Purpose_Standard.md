# Platform Naming and Purpose Standard

**Standard Version:** 1.0
**Status:** Approved Foundation
**Applies To:** All current and future AlTone engineering projects and platforms

## Purpose

This standard preserves the origin, approved spelling, defined meaning, and mission relationship of every AlTone project or platform name. It ensures that Alton, Bezalel, EXODUS, future approved AI systems, and future engineers can answer why a system carries its name without relying on conversation memory.

## Authority

- Alton Hampton approves the official name and its defined meaning.
- The project repository is authoritative for that project's approved name-and-purpose record.
- `Bezalel-Workbench/00_Foundation/Platform_Names_and_Biblical_Foundations.md` is the canonical ecosystem index for approved names.
- EXODUS may preserve an explicitly labeled field-reference copy for offline retrieval.
- A copied summary must identify its canonical source and must not silently create a competing authority.

## Required Document

Every active repository must provide either:

- `NAME_AND_BIBLICAL_FOUNDATION.md` at the repository root, or
- an approved equivalent in the repository's foundation folder.

The path should be declared as `authoritative_paths.name_and_biblical_foundation` in `project-manifest.yaml` when the manifest is adopted.

## Required Content

The document must contain:

1. Official project or platform name and spelling
2. Platform identity or repository classification
3. Biblical, linguistic, historical, or organizational foundation
4. Primary references
5. Approved meaning within the AlTone ecosystem
6. Relationship between the name and the actual mission
7. Guiding principles the platform should embody
8. Boundaries on what the name does not claim
9. A concise canonical answer suitable for Bezalel and EXODUS
10. The relationship to TECH BEE — Built With Purpose

## Biblical and Symbolic Accuracy

- Do not invent a biblical origin for a name that does not have one.
- Distinguish scripture, traditional name meanings, engineering interpretation, and organizational symbolism.
- Use references to identify the foundation; do not present paraphrase as a direct quotation.
- A symbolic biblical name does not make a machine divine, spiritual, angelic, morally authoritative, or operationally verified.
- The name-and-purpose record must not override current-state, architecture, testing, safety, or configuration documentation.

## TECH BEE — Built With Purpose

TECH BEE is the shared engineering emblem and working philosophy of the AlTone ecosystem. The bee is an engineering symbol rather than a biblical character or doctrine.

The bee represents purposeful work, cooperation, careful construction, stewardship, and turning gathered knowledge into something useful and lasting.

Built With Purpose means every project should have:

- A defined mission and reason for existing
- Clear human authority and responsibility
- Documentation sufficient for understanding and rebuilding
- Verification before capabilities are called operational
- Protection for private information and entrusted assets
- A commitment to safety, usefulness, teaching, and faithful stewardship

Technology is not built merely because it is possible. It is built to serve a meaningful and accountable purpose.

## Future Repository Rule

When a new project repository is created:

1. Select the approved repository family.
2. Copy `templates/Platform_Name_and_Biblical_Foundation.md` into the appropriate foundation location.
3. Complete it with approved facts.
4. Add the path to `project-manifest.yaml`.
5. Add or update the Bezalel Project Registry entry.
6. Add or update the canonical ecosystem naming index.
7. Re-index and test Bezalel and EXODUS retrieval before declaring the naming record available.

## Change Control

Changes to an approved project name, spelling, biblical foundation, canonical meaning, or TECH BEE definition require Alton Hampton's approval and an intentional GitHub record.
